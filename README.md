# FastDH 直播内容与上传包

[最新发行版](https://github.com/u1s1hm/fastdh-live-package/releases/latest) · [更新记录](CHANGELOG.md) · [版本号](VERSION) · [技能入口](SKILL.md)

一个面向 AI Agent 的内容制作技能：从现有视频、口头方向或不完整的 Markdown 文档出发，先引导明确直播内容、观众互动和停留理由，再生成或补齐 FastDH 上传文档与中文审核译本。

它是技能指令与辅助脚本，不是独立直播软件，也不是 FastDH 官方插件。平台规则依据和待核验能力见 [平台参考](references/platform.md)。

## 能做什么

- 新建或迁移直播内容：盘点素材，访谈，确认提纲，再制作。
- 补齐缺失的 Soul、Agents、LiveScript 或视频模板，保留已有节目方向。
- 修改任一语言后，同步另一语言和受影响的引用，分别重算行号。
- 为纳入节目的离线视频安排固定位置，预写前后口播，检查内容覆盖。

仅使用已有视频；不生成或修改视频，不设计视频播放失败与超时处理，不自动上传或开播。双语同步发生在调用技能时，不是后台文件监听服务。

## 安装

### 在 Codex 中安装

把以下请求发给具有 `skill-installer` 的 Codex：

```text
请使用 skill-installer 安装 https://github.com/u1s1hm/fastdh-live-package
仓库根目录就是技能目录，安装名称为 fastdh-live-package。
请固定到 v0.2.0；若已安装，先检查本地修改，再说明更新差异。
```

若直接使用 Codex 自带的安装脚本，其参数为：

```bash
python /absolute/path/to/skill-installer/scripts/install-skill-from-github.py --repo u1s1hm/fastdh-live-package --path . --name fastdh-live-package --ref v0.2.0
```

将脚本路径替换为所在环境的真实路径。安装器默认放入 `$CODEX_HOME/skills`（未设置时为 `~/.codex/skills`）；安装后在下一轮对话调用。具体环境以自带安装器为准。

### 手动安装或其他 Agent

从 [Releases](https://github.com/u1s1hm/fastdh-live-package/releases) 下载指定版本源码，解压并把文件夹命名为 `fastdh-live-package`，放到宿主支持的技能目录。确保 `SKILL.md` 直接位于该文件夹根目录，保留 `references/`、`agents/` 和 `scripts/` 的相对结构。

其他 Agent 的技能发现、问答控件和文件权限以宿主为准；尚未逐一验证兼容性。无法安装技能时，可以明确要求 Agent 阅读完整 `SKILL.md` 并按其引用继续读取参考资料。

## 使用前准备

| 提供的信息 | 说明 |
|---|---|
| 素材位置 | 待使用的全部现有视频；说明只读目录和允许复制的范围 |
| 现有文档 | 有什么提供什么，缺文件也可以开始 |
| 内容方向 | 想播什么、给谁看、希望用户如何参与；没想好可让 Agent 引导 |
| 约束 | 播出语言、大致时长或硬上限、必须保留与不接受的内容 |
| 资源信息 | 已有别名、模板编号和已核验的平台映射；未知可暂留待确认 |
| 输出位置 | 正式文档保存目录，中文译本放其子目录 |

需要能读写本地文件的 Agent。行号脚本使用 Python 3 标准库，无需 pip 依赖。视频探测和观看依赖宿主提供的工具；无法观察的画面由使用者补充确认。制作文档无需 FastDH 账号凭证。

## 三种常用请求

### 从素材开始

```text
使用 $fastdh-live-package。
素材目录：<素材绝对路径>，只读。
输出目录：<输出绝对路径>。
我想做一个英语直播间，时长约 20 分钟，主题是猫咪角色的日常陪伴。
请先检查素材，引导我明确内容、互动和停留理由，确认提纲后再生成。
```

### 补齐缺项

```text
使用 $fastdh-live-package。
这里已有 Soul、Agents 和视频模板，但缺 LiveScript 与编排索引：<目录>。
沿用现有人设与内容方向，先说明缺项和冲突，再补齐必要文件及中文译本。
```

### 修改并同步

```text
使用 $fastdh-live-package。
我修改了 <中文译本文件路径> 的 U03：<明确修改意图>。
请同步英文含义，检查受影响的口播、映射与编排，并分别重算两种语言的行号。
```

示例的主题和 20 分钟仅是示例，不是技能默认参数。若需要点舞、至少四个互动窗口或特殊循环，请明确提出，由 Agent 根据素材和平台能力确认方案。

## 实际使用流程

1. Agent 盘点素材与文档，区分已知信息和缺口。
2. 每轮提出少量问题，优先使用宿主问答控件，否则给编号选项。
3. 新建、迁移或实质重构时展示提纲；即使完整委托，也先确认提纲。
4. 获准后生成文档及中文译本，检查内容、资源覆盖、双语含义和行号。
5. 使用者按内部检查文件，在 FastDH 中配置并核验实际播放。

## 会生成哪些文件

N 为本次管理的视频数量，包含 LIPSYNC 底板。每种语言为 N+5 个正式 Markdown 文件；英文放指定目录，中文放 `中文译本/`。

| 文件 | 用途 | 是否上传 FastDH |
|---|---|---|
| `Soul.md` | 人设、语气示例、事实边界 | 是 |
| `Agents.md` | 回复、互动、安全和能力边界 | 是 |
| `LiveScript.md` | 固定口播与简短段尾配置说明 | 是，按口播行范围配置 |
| `video_template_N.md` | 每条视频的资源标识与 Introduction | 是 |
| `LiveScript_Nonempty_Line_Index.md` | 编排、口播行号和时长依据 | 否，内部检查与配置参考 |
| `Media_Resources_and_Pending_Checks.md` | 媒体映射、互动约定和未决项 | 否，内部检查与配置参考 |

中文是审核译本，不作为另一套英语播出配置上传。具体格式见 [文件职责](references/deliverables.md)。本仓库的 README、CHANGELOG 和 VERSION 属于技能发布资料，不会加入直播上传包。

## 媒体别名建议

保留本地视频原文件名，使用媒体映射表关联 FastDH 别名。别名限 3–32 个字符，仅小写字母、数字、下划线，字母开头、字母或数字结尾，且项目内唯一。

新别名建议统一使用 `clip_01`（离线视频）、`lip_01`（LIPSYNC 底板）、`int_01`（独立互动底板）。已有合规别名可保留。互动窗口复用 LIPSYNC 底板时沿用原别名，无需复制资源；前缀仅表示用途，不决定平台媒体类别。详见 [别名规则](references/deliverables.md#别名与互动底板)。

## 单独使用行号工具

在本仓库根目录运行：

```bash
python scripts/script_index.py "/absolute/path/LiveScript.md"
python scripts/script_index.py "/absolute/path/中文译本/LiveScript.md"
```

工具只读输入，以 JSON 输出非空行范围与错误，不修改文件。退出码 `0` 表示格式检查通过，`1` 表示脚本结构错误，`2` 表示文件读取错误。配置说明也占非空行，但不能包含在口播范围内。完整支持格式见 [检查说明](references/review.md)。通过检查不代表平台实际播放已验证。

## 制作完成前会检查什么

除文件数量与行号外，v0.2.0 增加逐项验收：

- 对照素材证据、Introduction 和前后口播，核验动作及音频描述；抽帧不等于完整观看或听取。
- 对照互动邀请、观众输入和实际反馈，明确所需台词、主题与状态从哪里进入主播或后台配置。
- 迁移时保留原方案的角色辨识度和有效信息；未核验曲名等记录为待确认，而非静默丢弃。
- 检查各段是否有新的内容或体验，双语是否包含相同的来源、说明和确认状态。

编排索引与媒体映射仍不上传。依赖它们的台词或话题必须明确转入上传文档或已核验的后台配置入口；没有确认入口时，该部分保持待核验。结构检查通过不代表内容、配置或实际播放全部通过。

## 版本与升级

`VERSION` 记录当前源码版本；Git 标签使用 `v主版本.次版本.修订号`，发行说明见 CHANGELOG 和对应 Release。

- 当前 `0.x` 为初期版本。影响交付格式或工作流程的变化提升次版本，并明确迁移影响。
- 兼容的说明修正和缺陷修复提升修订号。
- 从 1.0 起，破坏兼容性的变更提升主版本；兼容功能提升次版本。

升级前阅读目标版本说明，保留自己的本地修改，再更新技能文件。升级技能不会自动迁移既有直播文档；需要时单独调用技能并说明修改范围。使用已发布标签可固定版本，`main` 可能包含尚未正式发布的修改。
