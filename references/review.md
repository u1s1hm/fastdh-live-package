# 交付前检查

制作完成要求内容和结构都通过。检查过程在工作区执行，结果简述在回复中；不新增交付报告。

## 内容自检

- 每个主要段落有具体信息、情节、笑点、情绪或展示目的；没有只为凑时长的流水账。
- 人设体现在表达中，而不是每段自报身份。语气示例有情境变化，不反复套同一句。
- 不机械欢迎、感谢、反问、励志总结；普通问题直接回答，幽默符合语境。
- 承接符合已确认视频画面、音频和作用，不把观察不足写成事实。
- 互动邀请说明实际参与方式，反馈符合确认体验，频率不破坏内容节奏。
- 没有弹幕也能推进；不编造观众反应或具体点播结果。
- 设定事实、未设定事项及完整安全条款双语一致。

修正不改变提纲的内容问题可直接进行。需要改变主线、人设或互动时返回确认，而不是以“优化”名义换节目。

## 结构自检

- 本次正式 MD 每语言 N+5 个，一视频一模板；无新添报告、JSON、重复大小写文件。已有无关文件不计为本次新增。
- 文件名、模板 ID、类别值、视频文件、平台标识没有混用；建议映射明确标记。
- 所有纳入本场的离线视频有固定位置及前后承接；排除项已有用户确认。
- 编排顺序与段尾说明、互动映射一致，最后收尾符合确认的结束／循环要求。
- 分别计算语言版本非空行；所有口播覆盖且不含说明；存在换行变化时不沿用旧索引。
- 双语文件与板块、单元、资源关联完整；允许行数不同，数字与含义必须核对。
- 时长是一个正常区间，有依据；未知 TTS 明确是估算，不把媒体文件长度当口播上限。
- 无未解决的制作冲突被包装成“已完成”；未知平台能力只阻止依赖它的部分定稿。
- 受保护原文件／媒体未改动；复制媒体字节一致。

## 行号工具

`scripts/script_index.py` 是只读计算器。支持新规范和已见旧稿的段尾说明：

```text
[Configuration | U01 end] ...
[Configuration note | U01 end] ...
【配置说明｜U01结束】...
[配置说明 | U01结束] ...
```

每段必须有结束说明，空行不计数。重复单元、连续说明导致空段、说明后残留未归属台词、疑似说明拼写错误、混入 Markdown 元数据时返回错误并退出非零。它不验证平台是否支持、语义是否准确、每句是否自然、资源是否覆盖，也不要求中文与英文单元行数一致。

工具输出 JSON 到标准输出，供 Agent 读取并填入现有 MD 索引；不是平台导入格式，也不另存到交付目录。不得拿工具 PASS 替代内容自检或人工核验。

## 技能开发回归场景

修改本技能时用这些场景检查行为，不把测试文件加入用户上传包：

1. 只有视频和“做得有趣”：先内容访谈，不立即套数字点播。
2. “全部帮我定并生成”：询问必要约束，仍提交提纲确认后才写正式文件。
3. 已有 MIYA 角色但缺脚本：沿用角色，不套 Petopia 的世界观和时长。
4. 30 条舞蹈、10 分钟聊天目标：指出覆盖冲突，请用户选择，不暗中删素材。
5. 仅补索引但九个代码只有八条媒体：指出实质冲突并确认修复范围。
6. 用户改中文、句数变化：同步含义、单独重算双侧行号，不强制同句数。
7. 自然语言点播能力未知：先需求和核验点，不改为数字模式，不声称可上传。
8. 只改一句话：直接落盘并联动译文、索引，不重走全部访谈。
9. 同名不同媒体版本：不覆盖、不自动改名，明确选择再维护引用。
10. 模型想追加故障兜底清单：排除播放失败／超时设计；正常内容承接继续生成。
