# 访谈与提纲

访谈用于澄清使用者的节目，不是收集一堆后台参数。先从已给资料形成简短理解，只追问影响方向的缺口。新会话可读取已有编排索引中的内容约定和媒体映射中的互动约定；核对是否仍适用，不要求从头回答。

## 交互方式

优先发现并使用所在 Agent 支持的问答控件，同时遵守工具模式、参数和权限限制。单选不伪装为多选，文本控件不用于文件上传。没有合适工具时给编号选项和自由补充入口。每轮通常 1—3 个相关问题，依据答案展开，不一次抛出整张问卷。

选项用具体体验描述，不用“提升黏性”等抽象词。推荐项可以标明理由，不能代用户选中。用户不回答或工具无返回时，继续可独立进行的盘点，不把沉默当批准。

## 第一轮：想播什么、给谁看

先提取已有主题、人设和素材类型。询问：

- 主要受众、节目目的、语言及希望的观看感受。
- 主播是谁，观众能看到什么具体内容；没有弹幕时有什么看点。
- 喜欢的参考、希望保留的旧内容、明确不接受的方向。
- 目标时长是大约值还是硬上限，是否循环。

若只有“好看、有趣”，给两三个与实际素材相符的例子：如角色日常脱口秀、围绕目标的排练过程、故事串联的视频展示。说明各自观众能看到什么，请用户选择或组合。不先生成整套方案。

## 第二轮：观众为何留下

将抽象目标变成可写进节目的机制：

- 值得等待的是下段故事、下一次展示、主播回答，还是角色陪伴？
- 内容如何逐步变化，如何欢迎中途进场者，又不反复重开场？
- 哪些段落有实际信息、情节、笑点或情绪推进？

不用承诺停留率指标。使用者没想法时提供例子帮助判断；得到明确委托后可完善执行细节。

## 第三轮：素材用途

展示“文件／已有别名／已知画面／待确认用途”的简表。批量确认同类素材，只有真正不同的问题才逐条问。

画面描述先依据文件或观看证据起草，用途和情境由使用者确认。区分观察与推断。素材不能区分时可保留编号，不凭空指定舞种。缺失别名时建议简单、唯一的值，再确认。音频仅在影响理解或使用时追问；有音轨不能推断它有音乐或人声。

## 第四轮：互动访谈

没有充分了解下面信息前，不直接生成互动方案：

| 维度 | 要明确的问题 |
|---|---|
| 目的 | 聊天陪伴、点播、参与故事、选择方向，还是其他体验？ |
| 权限 | 哪些行为能触发视频，哪些只能回应，哪些不开放？ |
| 输入 | 精确代码、自然语言或组合；精确选片还是模型判断？ |
| 时机 | 窗口内还是其他阶段；窗口外评论期望怎样处理？ |
| 普通聊天 | 是否回答问候、夸奖、问题；使用语音还是文字？ |
| 反馈 | 观众怎样知道自己的参与生效：视频、语音、文字或组合？ |
| 节奏 | 多少次机会、每次多长、多少表演；互动与固定内容谁占主导？ |
| 重复 | 可否重复播放；是否允许模型自主选择？ |
| 偏好 | 沿用什么玩法，明确不想要什么？ |

先明确体验，再提出参数。用户不懂平台术语时用例子解释。尚未明确的窗口数量、代码、静默／发声模式不得用旧项目值填入。

将结果复述成短约定，区分需求与平台支持。例如：“观众用自然语言点播，系统从已确认素材里选择；普通问候希望语音回复。窗口内发声能力尚待运营核验。”未知能力按 platform.md 处理。

## 提纲与授权

正式制作前的提纲应包括：

1. 主播定位与表达风格。
2. 本场主线、具体看点、停留理由。
3. 各段讲什么，媒体大致在哪里出现。
4. 互动玩法、输入、时机与参与反馈。
5. 预计时长区间、素材覆盖与明确排除项。
6. 未决问题和已委托给 Agent 决定的部分。

用户批准后，措辞、笑点、自然转场和不改变体验的局部编排自行完善。即使“全部帮我定”也需要这一轮提纲确认；必要约束先问清，不把完全委托理解为无约束。

新建任务既需要明确制作委托，也需要提纲批准。若一开始已明确要求生成，不再索取同一许可。改主题、人设、核心互动、素材取舍或明显偏离时长目标时重新确认；只修一句话不重走完整访谈。
