# 补齐、双向同步与媒体保护

## 任务边界

| 请求 | 默认动作 |
|---|---|
| 补齐 | 新增缺项，提取已有内容；必须修复的实质冲突先说明并确认范围 |
| 修改 | 根据明确意图修改实际文件，同步另一语言及受影响引用 |
| 新建／迁移 | 访谈、提纲批准后完整制作 |
| 讨论／草稿 | 对话中展示，不自动写正式文件 |

确认过的授权持续有效。普通措辞修改无需再次审批全部节目。主题、人设、核心互动、素材取舍或明显时长偏移需重新确认。有效内容移到合适板块、重复内容合并；不能因格式简化而抹去业务要求。无关旧文件不清理。

## 迁移时保留原内容

先从原资料提取角色事实、独特表达与幽默、节目主线、媒体名称或曲名、互动方式及时间约束，作为本次修改的基线。对照新稿检查哪些被保留、改写、排除或仍待核验；检查过程留在工作区，不新增交付文件。

原资料提到的曲名或动作不等于已验证的视频事实。尚不能核对时，在现有媒体映射的待确认项保留候选值、来源与对应素材，不静默删除，也不直接写成已确认口播。改变角色核心、玩法或重要内容取舍时按任务授权确认；普通措辞调整自行完成。

简化结构应保留有效世界观、角色的犀利／俏皮等辨识度、完整安全要求和必要来源。已批准的虚构故事可以在边界内创作；区分虚构人物经历与真实人物关系、真实观众留言和实际执行结果。需要扩展未设定的重要背景时先确认，不以事实约束抹去所有创作空间。

## 固定口播插入与移动

修复承接前先判断它是否每场必经。主线台词插入实际播放位置，条件触发台词按 deliverables.md 单列；优先保留稳定 ID，不为避免重算索引把主线台词追加到文件末尾。同步两种语言的对应位置，再分别重算索引，并核对段尾 Next、后台行范围和其他受影响引用。发布文档不能代替更新已配置后台；后台尚未更新时记录待配置。

## 双向同步

英文不是永远优先，最近修改时间也不等于最终意图。以明确的用户修改指令为依据；没有指令而两边产生事实／规则／人物／资源／节目逻辑冲突时，列出对应差异让用户选。自然语言表达差异不必逐句询问。

关联单位：同名文件、对应板块、稳定 U 单元、稳定资源别名。含义、语气、事实和配置一致优先于句数一致。允许一边拆句、另一边合句；分别计算每种语言的索引，禁止直接复制行号。

| 修改 | 必须检查的关联 |
|---|---|
| 人设事实或语气 | 对侧 Soul、受影响 Agents／台词／示例 |
| 互动方式或代码 | 双侧 Agents、参与口播、媒体互动映射及编排 |
| 台词增删或拆句 | 对侧对应单元、两侧行号与时长影响 |
| 资源别名或文件选择 | 模板字段、映射、编排、提到该资源的文案 |
| Introduction 画面或用途 | 对侧简介，以及依赖该描述的台词和模型调度意图 |
| 单纯译文润色 | 原文含义是否需改；无意图变化则不反向歪曲原文 |

中文是审核参考，翻译“全程英语”时仍保留该要求。英语正式时长按英语 TTS 计算。转换为中文正式播出属于新的制作变更，不直接沿用英语时长。

除正文外，还核对来源网址、事实确认状态、配置说明和待确认项；链接及机器标识可原样保留，不能只在一侧遗漏整个板块。

本技能仅在调用时检查同步，不承诺外部编辑后的后台自动监听。没有基线时，可比较内容并读取已确认约定，不能假装知道哪边被改过。最终不新增绑定数据库、隐藏状态文件或修订副本。

## 文件和媒体

已有媒体原地使用。跨目录复制前说明目标和大致容量，并取得相应确认；明确已有复制授权可直接执行。复制后按哈希验证原始字节一致。任何同名异版先明确选择，不覆盖、不擅自换名。必要更名由用户决定，并联动所有引用。

模板编号与别名保持稳定；新增使用未占用编号，不因排序变化重编号。重复媒体不自动删除或合并，先确认它们是否有不同运营用途。

只读输入目录要求必须遵守。制作前后核对本次受保护源文件；不创建临时文件、转码缓存或运行产物到源目录。用户自己的未提交修改不能覆盖。

默认正式文件直接放指定目录，中文放子目录；不要为了“完整包”额外套一层目录。打包、安装、发布、上传另按用户请求处理。
